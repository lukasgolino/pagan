# WEBSITE_PLAN.md — the PAGAN website

Brief for whoever builds the site (an agent or a person). It assumes the MCP server
([MCP_PLAN.md](MCP_PLAN.md)) is done and released. Goal: make an indie developer or an agent builder
understand in 30 seconds what PAGAN is, believe the art is real, and install it in one line.

## 1. The pitch

**You speak English. Your agent speaks PAGAN.**

PAGAN (Pixel Art Grammar And Notation) is a language for game art: palettes, sprites, tiles, 3D models,
animations and style rules, written as plain text. You don't need to learn it. With the PAGAN skill or
MCP server, your AI agent becomes the translator: you say "give the zombie an attack animation", the
agent writes PAGAN, PAGAN checks it and renders it, and your game gets engine-ready sprites.

The page tells it as a three-step diagram, drawn literally:

```
 You (English)            Agent (Claude + PAGAN skill/MCP)            PAGAN            Your game
 "a zombie that      ->   writes zombie.model.yaml, lints,      ->   renders 8     ->  zombie.png
  shambles towards        previews, looks at the result,             headings,         zombie.tres
  the player"             fixes it                                   walk cycle        manifest.json
```

Tagline candidates: "Speak game. Get pixel art." / "Pixel art, in a language your agent speaks." /
"The art language for AI agents." Owner picks one.

Free and open source (MIT), local, offline, no account, no credits, no API key. The art is yours.

## 2. What's unique (researched 2026-10-17; re-check before launch)

The landscape has three kinds of tool:

| | Image-model generators (PixelLab, Ludo, Sprite AI, Retro Diffusion, SpriteLab) | Pixel-pushing MCP servers (pixel-mcp, pixscii, Aseprite MCPs) | **PAGAN** |
|---|---|---|---|
| How art is made | Diffusion model; you prompt, it paints | The agent sets pixels/draws shapes through tool calls | The agent writes a **source file** (text notation) that PAGAN compiles |
| Art is stored as | PNGs | PNGs / .aseprite files | **Text in git**: diffable, reviewable, editable by hand or by agent |
| Cost / access | Subscriptions or credits, cloud, account | Free; some need Aseprite (paid) | **Free forever, MIT, offline** |
| Consistent rotations | 4/8 directions generated by a model (can drift) | Drawn by hand per direction | **3D voxel models rendered exactly** in 1-32 headings with one project camera and light |
| Animation consistency | Model-generated frames | Manual | Poses move parts by whole voxels; lint W007 measures frame-to-frame churn; previews highlight every changed pixel |
| Style consistency across a game | Per prompt / style references | None | **Project-wide**: shared palettes with ramps, camera, light, style versions; change one setting and every asset updates |
| Quality checks | — | — | **Linter** (orphan pixels, jitter, ramp misuse, outline clipping...) the agent reads and fixes |
| Engine output | PNG sheets, some JSON atlases | PNG | `manifest.json` contract for any engine, Godot SpriteFrames/TileSet resources verified in headless Godot, normal maps, palette-swap tables |
| Long-term project | — | — | BRIEF.md + STYLE.md memory, asset status, style changelog, `pagan status` |
| Deterministic | No | Yes | Yes: byte-identical builds |

Evidence for the claims about others (keep the comparison factual and dated; don't sneer):
- PixelLab: 4/8-direction characters, animation, tilesets, an official MCP server; needs an account and
  token. https://mcpservers.org/servers/pixellab-code/pixellab-mcp · https://ludo.ai/compare/best-ai-pixel-art-generators
- pixel-mcp: canvases, set_pixel/rect/line, PNG export, no palettes or animation.
  https://github.com/adrianoamaral/pixel-mcp
- pixscii (closest idea: one character per pixel, PICO-8/gameboy palettes, MCP, MIT): no 3D, lint or
  engine export found. https://github.com/rxolve/pixscii
- Aseprite MCPs: drive a local Aseprite install. https://images.glama.ai/mcp/servers/integrations/aseprite

PAGAN's differentiators, ranked for the page:
1. **Art as source code.** Text the agent writes and you can read, diff, review and version.
2. **3D in, perfect 2D out.** One voxel model gives every heading and animation, consistently lit.
3. **One style, everywhere, forever.** Palettes + project light + style versions: "make it darker" is
   one command for the whole game.
4. **It checks its own work.** Lint + previews the agent looks at, so it fixes its own mistakes.
5. **Engine-ready.** manifest.json for any engine; Godot resources out of the box.
6. **Free, open, local.** No credits, no cloud, MIT.
7. **Built for agents.** Skill + MCP + an orchestrator contract (an agent building your game calls PAGAN
   like a service).

Be honest about where PAGAN loses, in a short FAQ: it isn't a painter. For one-off, organic,
illustration-heavy art, a diffusion tool is faster. PAGAN wins on a whole game's worth of consistent,
animated, rotatable, maintainable assets.

## 4. The interactive demo (scripted, real art)

A chat UI between "You" and "Agent". The conversation is **scripted**: the visitor picks from 2-3
suggested replies at each step. **Every image is real PAGAN output**, rendered from source files that
live in the repo. Label it plainly: "A scripted conversation. The art and source files are real PAGAN
output." Don't present the chat as a live AI session.

Each agent turn shows:
- the agent's short reply ("Done: 8 headings, 6-frame walk, palette `grave`"),
- the art: an animated preview at ×4 that can be rotated where it has headings,
- a collapsible **"what the agent wrote"**: the source diff for that step (YAML), and the lint line
  ("0 errors, 0 warnings"),
- a collapsible **"what your game gets"**: the manifest entry / files.

Scenarios (each is a tree 3-4 steps deep; branches converge to keep the asset count sane):

1. **Zombie game.** "I'm making a top-down zombie game, give me a zombie that shambles towards the player"
   → 3D zombie model, 8 headings, walk.
   → "give him an attack animation" (lunge with arms) / "make him more rotten" (palette ramp swap) /
   "now a whole horde" (variants: skin tones, torn clothes via variant_axes).
   → "make the night darker" (palette adjust across zombie + tiles: before/after).
2. **Sailing game.** "I'm making a sailing game, give me a ship"
   → a hull with masts → "give it sails" → "16 headings so it turns smoothly" → "team colours for
   4 players" (variants) / "show it damaged" (hidden-part poses: torn sails, listing).
3. **Neon space shooter** (shows PAGAN isn't only pixel art). "High-contrast arcade, not pixel art"
   → a flat triangle ship with a rim (supersampled, smooth) → "lasers" → "explosion".
4. **Cosy farm** (2D and tiles). "A farm tileset" → grass/dirt corner set → "animated water" → "make
   it autumn" (palette swap of the whole scene).

Branch rule: at most ~25 asset states in total. Every state is a real PAGAN project snapshot.

## 5. How the demo art is produced (and kept real)

- `examples/website/` is a PAGAN project (its own palettes) with one folder per scenario step:
  `steps/<scenario>/<step>/` holding the source files for that state (copied forward and edited, so
  each step is a real diff from the previous one).
- `tools/build_site_assets.py` (in this repo) builds every step with PAGAN, exports GIFs/PNG strips and
  heading strips for rotation, the source diffs and lint summaries, and writes
  `site/public/demo/<scenario>/<step>.json` plus images. Deterministic, so re-runs don't churn.
- CI rebuilds the demo assets and fails if they differ from the committed ones (same pattern as
  `examples/godot`). The website can never show art PAGAN doesn't produce.
- The art is made the way users would make it: an agent with the PAGAN skill, from the scripted
  prompts. Then the owner reviews it. **Art-quality gate:** nothing ships on the site until the owner
  approves every state (`pagan mark --status approved`). The demo is the product's first impression, and
  weak art here costs more than any missing feature.

## 6. Tech

- Static site: **Astro** (fast, content-first, islands for the interactive bits) or plain Vite +
  TypeScript; no backend. Host on **GitHub Pages** (free, next to the repo) or Cloudflare Pages.
- Pixel rendering: `image-rendering: pixelated`, integer scaling only; heading scrubbing on a
  `<canvas>` from a heading strip; palette recolouring in the browser using the manifest `swap` tables
  (the same thing a game shader does: a nice proof that the data is usable).
- Docs: generate pages from `src/pagan/skill/reference.md` and the CHANGELOG at build time (one source
  of truth).
- Fonts and branding: a pixel display font for headings (e.g. a free OFL font) and a clean sans for
  body text; dark theme by default, with the demo palettes as accent colours. A logo made in PAGAN
  itself (a sprite in `examples/website`).
- Performance: total demo payload under ~5 MB, images lazy-loaded, GIFs replaced by PNG strips animated
  in canvas where that's smaller.
- Accessibility: alt text from each asset's `description`, keyboard-operable chat choices, reduced
  motion respected (no autoplay).
- Analytics: none, or a privacy-friendly one (Plausible/GoatCounter). Owner decides.
- SEO/OG: one OG image per scenario (the gallery); pages for "AI pixel art for Godot", "pixel art MCP
  server" and "AI sprite generator, free and open source".
